# AGENTS.md — 이 프로젝트에서 에이전트가 지키는 규칙

당신은 이 폴더(작업 루트)에서 초파리 전뇌 시뮬레이션을 4단계로 만든다.
데이터·파라미터·통과 조건·검증기는 전부 이 폴더 안에 있다. 인터넷은 필요 없고, 써서도 안 된다.
이 문서가 지시의 단일 출처다. 다른 문서와 충돌하면 이 문서가 우선한다.

## 읽기 순서

1. `docs/TASK.md` — 오늘 할 일 4단계와 단계별 통과 조건
2. `docs/MODEL_SPEC.md` — 방정식·파라미터·게임 규칙·출력 파일 규격
3. `docs/DATA.md` — 데이터 파일 스키마와 로딩 예시

`README.md` 는 사람용이다. 읽어도 되지만 지시는 위 세 문서가 우선한다.

## 규칙 (전부 지킨다)

1. 한 단계씩. 현재 단계의 `python tests/verify.py --stage N` 이 PASS 하기 전에는 다음 단계를 시작하지 않는다.
2. 이 폴더가 작업 루트다. 모든 경로는 이 폴더 기준 상대경로. 절대경로·개인 환경 경로 금지. 작업 루트 밖의 파일은 읽지도 쓰지도 않는다.
3. `data/`, `docs/`, `tests/` 는 읽기 전용이다. 수정·이동·재생성 금지. 특히 `tests/verify.py` 를 고쳐서 통과시키는 것은 실패로 간주한다.
4. 인터넷 접근·다운로드·외부 데이터 사용 금지. 필요한 것은 이미 폴더 안에 있다.
5. 패키지는 `requirements.txt` 에 있는 것만 쓴다. 새 패키지 설치 금지.
6. 코드는 `src/` 에, 산출물은 `outputs/` 에. 파일 이름은 `docs/TASK.md` 에 적힌 대로 정확히. 이름이 다르면 verify 가 실패한다.
7. `outputs/` 의 모든 파일은 `src/` 의 스크립트가 만들어야 한다. 손으로 쓴 결과 파일은 실패로 간주한다.
8. 모델 파라미터(`docs/MODEL_SPEC.md` §1)를 바꾸지 않는다. 결과가 안 나오면 파라미터가 아니라 구현을 의심한다.
9. 무작위성(포아송 자극)은 지정된 시드로 고정한다. 같은 코드는 같은 결과를 내야 한다.
10. 스펙에 없는 기능(웹 UI, 학습 규칙, 다른 뉴런 모델, 익룡·숙이기 등)을 추가하지 않는다. 필요해 보이면 만들지 말고 `outputs/QUESTIONS.md` 에 질문으로 남긴다.
11. 설명·주석·보고는 한국어, 코드 식별자는 영어 관례.
12. 각 단계 스크립트는 `python src/stepN_*.py` 한 번으로(인자 없이) 그 단계의 산출물을 전부 만들어야 한다. 실행 시간(wall time)을 `outputs/0N_summary.json` 의 `wall_seconds` 에 기록한다. 실행이 중간에 끊겨도 다시 실행하면 이어서 갈 수 있게(이미 만든 결과는 건너뛰게) 짜는 것을 권장한다.
13. 실패하면 숨기지 않는다. 오류 전문과 시도한 것을 보고하고, 같은 시도를 3번 넘게 반복하지 않는다. 3번 실패하면 멈추고 사람에게 묻는다.
14. 긴 실행은 도구 탓이지 코드 탓이 아니다. ③은 1~2분, ④는 2~5분 걸리는 것이 정상이다. 명령 실행 도구에 시간 제한(흔히 2분)이 있으면 제한을 10분 이상으로 늘리거나, `nohup python src/step4_dino.py > outputs/04_run.log 2>&1 &` 처럼 백그라운드로 돌리고 로그 파일로 진행을 확인한다. 시간 제한에 걸렸다고 코드를 최적화하러 돌아가지 않는다 — 실행 방식을 바꾼다.
15. 정답 코드를 찾으려 하지 않는다. 이 폴더 안에 정답은 없고, 인터넷은 금지다.

## 시작 전 확인

```
python -c "import numpy, scipy, pandas, pyarrow, matplotlib, PIL; print('ok')"
```

`ok` 가 안 나오면 `requirements.txt` 를 설치하고(로컬이면 `setup_env.bat` / `setup_env.sh`), 그래도 안 되면 멈추고 사람에게 알린다.

## 완료 보고 형식 (단계마다)

- 단계 번호와 한 줄 요약
- 만든 파일 목록(`src/`, `outputs/`)
- `python tests/verify.py --stage N` 출력 전문
- wall time
- 스펙과 다르게 한 곳이 있으면 이유와 함께 명시(없으면 "없음")

4단계가 끝나면 `python tests/verify.py --all` 의 출력을 `outputs/verify_all.txt` 에 저장하고, 단계별 wall time 을 표로 정리해 보고한다.
